# encoder candidate research

research snapshot: 2026-10-24. this is a shortlist and test design, not a tool selection, legal opinion, speed claim, or quality claim. no candidate CLI executable has been bundled or measured in this repository. pin an upstream tag and source commit before building or benchmarking.

## shortlist

| path | upstream evidence | reason to measure | distribution and product risks |
| --- | --- | --- | --- |
| PNG frames → `gifski` CLI | [manifest](https://github.com/ImageOptim/gifski/blob/main/Cargo.toml) declares `AGPL-3.0-or-later`; [CLI README](https://github.com/ImageOptim/gifski/blob/main/README.md#from-png-frames) documents direct PNG-frame input, resizing, and quality controls. its default features include `gifsicle` and `binary`; FFmpeg video support is optional. current CLI source sets quality to 90 by default, supports `--no-sort`, and assigns evenly spaced timestamps to PNG inputs from `--fps`; it keeps every input frame rather than resampling or dropping frames ([argument definitions](https://github.com/ImageOptim/gifski/blob/main/src/bin/gifski.rs#L1628-L1796), [PNG timing](https://github.com/ImageOptim/gifski/blob/main/src/bin/png.rs#L308-L352)). | direct frame input and the same declared license as gifferent make this the first encoder candidate. | audit the exact `Cargo.lock`, source of the internal `gifsicle` feature, transitive notices, build flags, and source-offer obligations at the pinned revision. the [publisher's inherited pngquant notices](https://gif.ski/license.html) must be checked against the built version. documented quality controls do **not** establish an independent dithering-strength slider; prove a real, monotonic dither control before using this path alone for that approved control. |
| PNG frames → `magick` CLI | [ImageMagick's license](https://github.com/ImageMagick/ImageMagick/blob/main/LICENSE) permits redistribution with its license and attribution and says it is GPLv3-compatible. [CLI options](https://imagemagick.org/command-line-options/) document GIF output, color reduction, Floyd–Steinberg dithering, and `-define dither:diffusion-amount=35%`; [layer options](https://legacy.imagemagick.org/script/command-line-options.php/) document animation optimization. set `-loop 0` after the input frames so the output setting follows the inputs ([animation guidance](https://usage.imagemagick.org/anim_basics/)). | credible alternate complete encoder with a documented numeric dither-strength control and an optimizer. | a distributable macOS build may contain dynamic libraries, coders, and configuration files. inventory and sign every required component, its license, and exact architecture; prohibit unused delegates and remote/unsafe coders with a [restrictive policy](https://imagemagick.org/security-policy/). verify the pinned build actually changes output when diffusion amount changes. a past [upstream bug report](https://github.com/ImageMagick/ImageMagick/issues/1584) shows this cannot be assumed from documentation alone. |
| PNG frames → ImageIO GIF → `gifsicle` CLI | [Gifsicle's README](https://github.com/kohler/gifsicle#copyrightlicense) declares GPL version 2 only and an alternative license with conditions; its [manual](https://github.com/kohler/gifsicle/blob/master/gifsicle.1) documents optimization and lossy options. | useful optimizer comparison after measuring the whole PNG-to-GIF path, including ImageIO creation. | GPL-2.0-only is incompatible with AGPLv3 for combined code according to [GNU's license list](https://www.gnu.org/licenses/license-list.html#AGPLv3.0). a separately executed CLI may be a distinct work under [GNU's aggregation guidance](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation), but that depends on the actual integration and packaging. do not link or copy its code, and do not ship this path without a reviewed license determination. its alternative license is not an automatic blanket exemption. |

`gifski` is the **provisional lead for the original GIF**, subject to measurements, license audit, and proof that the approved dither control can be implemented. measure ImageMagick as a complete alternative and possible optimizer. keep `gifsicle` research-only until the separate-program licensing question is resolved. an existing `ffmpeg` on a developer machine is not a release dependency or a measured candidate for this decision; bundling it would require its own exact build, codec, and license audit. do not use optional FFmpeg support in the `gifski` build under evaluation.

## benchmark inputs and execution

1. generate the same synthetic source once per case with [`generate_fixture.py`](generate_fixture.py). start with the existing mixed 640×360, 240-frame, 24-fps fixture; add a mostly static UI, fast-scroll UI, and high-motion case before final selection. add a 30-second case and a full-display resolution once the small case works. store all generated media under ignored `Benchmarks/generated/` and outputs under ignored `Benchmarks/outputs/`. never use private screen content in committed evidence.
2. pin source tags **and commit hashes**, dependency lockfiles, compiler versions, build options, macOS minimum target, binary SHA-256, `file`/`lipo` architecture output, linked libraries (`otool -L`), `--version`, and help output. record the ImageMagick policy and configuration paths. use binaries built for the intended distribution; a Homebrew binary is only an exploratory prototype.
3. run complete paths from identical PNGs with identical frame order, dimensions, nominal timestamps, and loop setting: **a** `gifski` CLI; **b** `magick` CLI with and without `-layers Optimize`; **c** ImageIO baseline; **d** ImageIO followed by `gifsicle` only if license review allows more than research use. include PNG staging, process launch, encoding, optimization, output validation, and cleanup in end-to-end time. also record component times.
4. make one cold run, then at least seven warm runs per path on the same named Mac, OS, power mode, and thermal state. run paths in alternating order to limit heat/order bias. retain every raw sample; report median and p90 with the sample count. use separate process sampling for peak resident memory and CPU, and measure the largest temporary directory size during each run. record start-to-preview and stop-to-preview separately from total encode time when pipeline integration exists.
5. compare quality at equal output dimensions and source timing. sweep settings that genuinely change dither independently of resolution/palette/quality, then sweep palette, dimensions, and frame rate for size targeting. do not equate different tools' numeric quality values. record output bytes, decoded frame count, dimensions, per-frame delays, total duration, loop behavior, first preview readiness, and any frame merges. visually inspect the same frames at 1× and 2× for tiny text, flat UI edges, gradients, color shifts, temporal noise, cursor trails, and flashing. keep small comparison crops and obtain the architect's quality-floor review before choosing lossy presets.
6. test cancellation at launch, mid-encode, and during optimization; full disk, malformed frame, missing frame, nonzero exit, and interrupted output. prove bounded memory and temporary disk use, no stale temporary media, and no readable output being mistaken for a finished GIF. repeat on an Intel Mac if Intel distribution is in scope, and always verify the macOS 14 minimum on a real supported Mac.

GIF delays have centisecond granularity, so 24 fps cannot be represented by the same integer delay on every frame. validate cumulative duration and frame pacing from decoded output rather than assuming that a CLI's `--fps 24` or ImageMagick's [`-delay` syntax](https://legacy.imagemagick.org/script/command-line-options.php/) preserves 24 fps exactly. the final trim/speed/loop implementation must use the same timing contract as its preview.

## result record for each run

record a row containing: candidate/path; source revision and binary checksum; fixture manifest checksum; exact argument array and environment; run order and cold/warm state; elapsed time and first usable preview time; peak resident memory, CPU, and temporary disk; output bytes; decoded duration, frame count, dimensions, and loop value; exit status and validation result. attach the raw measurements, commands, visual samples, and reviewer notes to the benchmark result. choose a candidate only after both credible full paths have results on the agreed reference Mac and the distribution audit passes.

## release audit before bundling

- freeze and archive source revisions, `Cargo.lock` or equivalent dependencies, build recipes, full license texts, copyright notices, modified-file notices, and corresponding source access for any copyleft binary. review transitive licenses rather than inferring them from the top-level license.
- inspect every nested executable, dynamic library, and configuration file in the app bundle. build for required architectures and macOS 14, sign nested code before the app, notarize the final distribution, then install and launch it on a clean Mac without Homebrew or developer tools.
- confirm that the CLI processes only app-generated local paths and emits no network traffic. pass arguments as an array, never through a shell; use a restricted temporary workspace, bounded resources, and explicit cancellation.

the [benchmark machine](environment.md) is selected; measured results and the minimum visual quality remain gates in [`decisions.md`](../decisions.md). this research may narrow the candidates, but it cannot close those gates.
